# SurfLyrics for Windows

Windows 버전은 Windows 미디어 세션에서 Spotify 또는 Apple Music의 곡 정보와 재생 위치를 읽고 동기화 가사를 **작업 표시줄 오른쪽 알림 아이콘 바로 왼쪽**에 한 줄로 표시합니다. WPF/.NET 10으로 만들었으며, macOS 소스와 별도로 `windows/`에 있습니다.

## 실행

Windows 11 x64 또는 .NET 10이 지원하는 Windows 10 LTSC/Enterprise x64 환경을 사용하세요. 앱의 Windows API 대상은 Windows 10 2004 (19041) 이상입니다.

1. 빌드한 `SurfLyrics.exe`를 원하는 폴더에 둡니다. 자체 포함 빌드는 .NET을 별도로 설치하지 않아도 됩니다.
2. Spotify 또는 Apple Music 데스크톱 앱에서 음악을 재생합니다. Windows 미디어 컨트롤에 곡 정보를 제공하는 앱이어야 합니다.
3. `SurfLyrics.exe`를 실행합니다. 기본적으로 작업 표시줄에 가사를 표시하고, 간주와 대기 상태에는 음표를 표시합니다.

작업 표시줄의 가사를 클릭하면 가사 창 표시·설정·재생/일시정지·가사 다시 불러오기·종료 메뉴가 열립니다. 표시줄 배경이 그대로 보이는 투명 창을 알림 영역 옆에 배치하며 Explorer를 수정하거나 다시 시작하지 않습니다. 기본 모니터의 위쪽/아래쪽 가로 작업 표시줄에 맞춰 이동하고, 자동 숨김 또는 전체 화면 앱에서는 숨깁니다. 긴 가사는 말줄임으로 표시합니다. 보조 모니터의 작업 표시줄은 현재 지원하지 않습니다.

보조 가사 창은 트레이 아이콘을 두 번 클릭하거나 가사 메뉴에서 표시할 수 있습니다. 드래그로 옮길 수 있고 오른쪽 아래에서 크기를 조정할 수 있습니다. **고정**은 항상 위에 표시하는 옵션입니다. **—** 또는 창 닫기는 트레이로 숨깁니다. 트레이 우클릭 메뉴에서도 설정·가사 다시 불러오기·종료를 선택할 수 있습니다. `--window`로 실행하면 보조 창도 바로 표시합니다.

**설정**에서 가사 소스, 작업 표시줄 표시 여부·글자 크기, 보조 창 글자 크기, 가사 시간 보정(-5~+5초), 항상 위에 표시, Windows 로그인 시 실행을 바꿀 수 있습니다. 시간 보정이 양수이면 가사가 더 일찍 표시됩니다. 로그인 시 실행은 현재 실행 파일의 위치를 저장하므로 파일을 옮겼다면 다시 설정하세요. 관리자 권한과 상주 서비스는 필요하지 않습니다.

설정은 `%LOCALAPPDATA%\SurfLyrics\settings.json`에 저장합니다. 실제 가사, Spotify 쿠키·접근 토큰은 파일에 저장하지 않습니다. Musixmatch 임시 토큰은 앱 메모리에만 보관합니다.

**설정 → 표시 → 가사 전환 시 페이드 애니메이션**을 켜면 작업 표시줄과 보조 창의 가사가 바뀔 때 0.3초 동안 부드럽게 전환됩니다. 기본값은 켜짐입니다. 끄면 즉시 전환되며, 재생 위치를 빠르게 바꾸어도 마지막 가사만 표시합니다.

## 가사 소스와 Spotify 연결

켜진 소스를 **Spotify 클라이언트 → LRCLIB → Musixmatch** 순서로 확인합니다. 가사를 찾지 못하거나 소스가 실패하면 다음 소스로 넘어갑니다. 시간 정보가 없는 가사는 재생 위치에 맞춘 가사로 표시하지 않습니다. 곡 변경 시 진행 중인 조회를 취소하고, 이전 곡의 응답을 새 곡에 표시하지 않습니다.

LRCLIB와 Musixmatch는 Spotify 연결 준비 없이 사용할 수 있습니다. Windows 미디어 세션에 제목·아티스트·길이가 충분히 제공되어야 올바른 가사를 찾을 수 있습니다. 검색 결과의 제목·아티스트·길이·에디션을 확인하고 서로 다른 녹음이 모호하게 일치하면 선택하지 않습니다.

Spotify 자체 가사를 사용하려면 **설정 → Spotify 다시 시작하여 가사 연결**을 누릅니다. 앱은 재시작 전에 확인하고, 현재 로그인된 Spotify를 로컬 디버깅 포트 `127.0.0.1:43827`로 실행합니다. Spotify가 재시작되므로 음악이 멈출 수 있습니다. **자동 재연결**은 기본적으로 꺼져 있고 사용자가 허용하면 연결이 끊어졌을 때 재시작합니다. 재시도 간격은 최소 2분입니다.

Spotify 설치 경로는 실행 중인 프로세스 또는 `%APPDATA%\Spotify\Spotify.exe`에서 찾습니다. Microsoft Store 설치본이 연결을 허용하지 않으면 일반 데스크톱 설치본을 사용하거나 다른 가사 소스를 이용하세요. Spotify 설정·바이너리를 수정하지 않습니다.

Windows 미디어 세션은 Spotify 곡 ID를 제공하지 않습니다. 로컬 연결이 준비되면 Spotify의 현재 재생 링크와 제목·아티스트를 확인하여 곡 ID를 얻고, macOS와 같은 `SpotifyClientBridge.js`를 실행합니다. 인증은 Spotify 내부에 남습니다. 재생 링크·메타데이터를 확인할 수 없거나 내부 구조가 달라진 경우 다른 소스를 사용합니다.

포트는 루프백에만 열려야 하며, 외부 주소·다른 포트·다른 페이지·자격 증명이나 쿼리가 포함된 WebSocket을 거부합니다. 같은 PC의 다른 프로세스도 디버깅 연결에 접근할 수 있습니다. 자동 연결을 끄면 이후 재시작을 중단하고, Spotify를 완전히 종료하면 디버깅 연결도 닫힙니다.

## 빌드와 검증

Windows x64, .NET 10 SDK, Node.js가 필요합니다. Visual Studio는 필수가 아닙니다.

```powershell
pwsh -File scripts/test-windows.ps1
pwsh -File scripts/build-windows.ps1 -Run
```

SDK가 PATH에 없으면 `-Dotnet C:\path\to\dotnet.exe`를 전달하세요. 빌드 결과는 무시된 `build/windows/win-x64/`에 생성됩니다. `-OutputDirectory`로 출력 폴더를 지정할 수 있습니다. 실행 파일, 라이선스, 이 안내가 포함됩니다. 스크립트는 릴리스를 게시하거나 배포 설정을 바꾸지 않습니다.

회귀 검사는 합성 데이터로 LRC 시간·오버플로·간주·탐색, 후보 매칭·모호성, Spotify 응답·루프백 검증, Musixmatch 토큰 거절·곡 확인, 소스 우선순위·실패 대체·캐시·취소, 재생·일시정지 시간 계산을 확인합니다. 기존 Node.js 검사는 공유 Spotify 브리지를 확인합니다. `SurfLyrics.exe --diagnostics C:\path\result.json`은 실제 UI와 트레이를 시작하고 Windows 미디어 API 접근 상태를 기록한 뒤 종료합니다. 곡명·가사·인증 정보는 진단 결과에 기록하지 않습니다.

실제 음악 앱에서 일시정지·재개·탐색·곡 전환·간주와 Spotify 재연결도 확인하세요. 자동 검사는 전체 음악 카탈로그와 이후 Spotify 버전의 호환성을 보장하지 않습니다.

### 2026-10-08 검증

Windows 11 x64 (빌드 26300)에서 Release 빌드가 오류·경고 없이 완료되었고 Windows 회귀 검사 49개와 공유 Spotify 브리지 검사 18개가 통과했습니다. 자체 포함 실행 파일에서 Windows 미디어 API 접근, 트레이·설정 창, 숨김/표시와 실제 위쪽 작업 표시줄의 알림 영역 옆 표시를 확인했습니다. Spotify 미디어 메타데이터와 곡명 표시도 확인했습니다. Windows Spotify 클라이언트의 가사 수신·재시작 복구와 실제 곡의 동기화 표시는 아직 확인하지 않았습니다.
