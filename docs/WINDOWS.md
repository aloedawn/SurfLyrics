# SurfLyrics for Windows

Windows 미디어 세션의 Spotify 또는 Apple Music 곡 정보와 재생 위치에 맞춰, 작업 표시줄 오른쪽 알림 아이콘 바로 왼쪽에 동기화 가사를 표시합니다. 가사 표시는 WPF/.NET 10, 설정창은 **WinUI 3 네이티브**이며 macOS 소스와 별도로 `windows/`에 있습니다.

## 실행

Windows 11 x64 또는 .NET 10이 지원하는 Windows 10 LTSC/Enterprise x64 환경을 사용하세요. Windows API 대상은 Windows 10 2004 (19041) 이상입니다.

1. 배포 폴더 전체를 원하는 위치에 보관합니다. `SurfLyrics.exe`와 `Settings/` 폴더가 함께 있어야 합니다.
2. Spotify 또는 Apple Music 데스크톱 앱에서 음악을 재생합니다. Windows 미디어 컨트롤에 곡 정보를 제공하는 앱이어야 합니다.
3. `SurfLyrics.exe`를 실행합니다. 기본적으로 작업 표시줄에 가사를 표시하고 간주와 대기 상태에는 음표를 표시합니다.

.NET과 Windows App SDK 런타임은 배포 폴더에 포함되어 별도 설치가 필요하지 않습니다. 가사에는 **Pretendard JP 1.3.9 Light (굵기 300)**를 앱에 포함하여 사용합니다. 시스템 폰트 설치는 필요하지 않습니다.

가사 영역은 클릭이 아래 작업 표시줄로 통과하는 표시 전용입니다. **트레이 음표 아이콘을 우클릭**하면 설정·재생/일시정지·가사 다시 불러오기·종료 메뉴가 열립니다. 메뉴의 배경과 글자색은 Windows 앱의 밝은/어두운 테마를 함께 따르고 고대비 모드에서는 시스템 색상을 사용합니다.

표시줄 배경이 보이는 투명 창을 알림 영역 옆에 배치합니다. 기본 모니터의 위쪽/아래쪽 가로 작업 표시줄에 맞춰 이동하고 자동 숨김 또는 전체 화면 앱에서는 숨깁니다. 가사는 말줄임이나 고정 너비 제한 없이 전체를 렌더링합니다. 전환 중에는 알림 아이콘과 겹칠 수 있고 화면 경계 밖은 화면에 표시되지 않습니다. 보조 모니터 작업 표시줄은 현재 지원하지 않습니다.

## 설정

WinUI 3의 네이티브 ToggleSwitch·Slider·Button·ContentDialog와 Mica 배경을 사용합니다. Windows 테마가 컨트롤의 색상을 결정합니다. 설정창은 별도 프로세스로 실행되며 현재 사용자만 접근 가능한 임시 이름의 named pipe로 가사 앱과 연결됩니다.

가사 소스, 자동 Spotify 연결, 작업 표시줄 표시·글자 크기, 시간 보정(-5~+5초), Windows 로그인 시 실행을 설정할 수 있습니다. 시간 보정이 양수이면 가사가 더 일찍 표시됩니다. 로그인 시 실행은 가사 앱 실행 파일의 경로를 저장하므로 폴더를 옮겼다면 다시 설정하세요.

**가사 전환 시 페이드**는 기본적으로 켜져 있습니다. 새 가사와 실제 글자 너비는 즉시 교체되고, 이전 가사는 120ms 동안 사라지며 새 가사는 180ms 동안 나타납니다. 페이드를 끄거나 Windows의 애니메이션이 꺼져 있으면 글자와 위치가 즉시 바뀝니다.

이동은 macOS에서 측정한 response 0.5초·damping 0.8 스프링 모델을 사용합니다. 현재 왼쪽 위치에서 전체 새 가사를 렌더링하고, 길어지면 왼쪽으로, 짧아지면 오른쪽으로 이동합니다. 약 1.516%의 작은 오버슈트가 있고 정착 시간은 이동 거리에 따라 달라집니다. 전환 도중 다른 가사가 들어오면 현재 위치와 속도를 이어받으며 같은 가사는 애니메이션을 다시 시작하지 않습니다. 글자를 가로로 늘리거나 줄이지 않습니다.

120Hz 모델의 정착 판정과 화면 렌더링을 분리하고 프레임 사이의 위치를 계산합니다. WPF 렌더링 시스템에 기본 모니터의 주사율을 요청하며 고정 15/30/60 FPS 타이머는 사용하지 않습니다. 실제 표시 속도는 주사율과 Windows 렌더링 성능에 따라 달라집니다. 모델 출처와 검증 범위는 [Windows 애니메이션 검증](WINDOWS_ANIMATION.md)에 기록했습니다.

설정은 `%LOCALAPPDATA%\SurfLyrics\settings.json`에 저장됩니다. 실제 가사, Spotify 쿠키와 접근 토큰은 파일에 저장하지 않습니다. Musixmatch 임시 토큰은 앱 메모리에만 보관합니다.

## 가사 소스와 Spotify 연결

켜진 소스를 **Spotify 클라이언트 → LRCLIB → Musixmatch** 순서로 확인합니다. 가사를 찾지 못하거나 요청이 실패하면 다음 소스로 넘어갑니다. 시간 정보가 없는 가사에는 시간을 만들지 않습니다. 곡 변경 시 이전 요청을 취소하고 이전 곡의 응답을 새 곡에 표시하지 않습니다.

LRCLIB와 Musixmatch는 Spotify 연결 준비 없이 사용할 수 있습니다. 제목·아티스트·길이·에디션을 확인하며 서로 다른 녹음이 모호하게 일치하면 선택하지 않습니다.

Spotify 자체 가사는 **설정 → Spotify 연결**로 준비합니다. 확인 후 현재 로그인된 Spotify를 `127.0.0.1:43827` 디버깅 연결로 실행합니다. Spotify가 다시 시작되면 음악이 멈출 수 있습니다. **Spotify 자동 연결**은 기본적으로 꺼져 있고 사용자가 허용하면 필요할 때 다시 시작합니다. 자동 재시도 간격은 최소 2분입니다.

일반 설치본과 **Microsoft Store 설치본**을 지원합니다. 일반 설치본은 실행 중인 앱 경로 또는 `%APPDATA%\Spotify\Spotify.exe`를 사용합니다. Store 설치본은 패키지를 찾고 Windows 앱 활성화 API의 기본 `Spotify` 진입점을 통해 실행합니다. 실행 파일 직접 호출이나 별도의 SpotifyLauncher 진입점은 사용하지 않습니다. 재시작 대상은 현재 세션에서 실행 경로가 확인된 Spotify 창입니다.

Windows 미디어 세션은 곡 ID를 제공하지 않습니다. Spotify의 현재 재생 링크가 곡을 가리키면 이를 사용하고, 앨범을 가리키면 현재 재생 컴포넌트의 제한된 상태에서 곡 ID를 확인합니다. 표시 제목·아티스트와 상태가 일치하고 곡 ID가 유일한 경우에만 가사를 요청합니다. React의 현재/대체 상태가 달라도 이전 곡을 선택하지 않도록 검증합니다.

가사 요청은 macOS와 같은 `SpotifyClientBridge.js`로 Spotify 내부의 인증된 클라이언트를 사용합니다. 인증은 Spotify 내부에 남고 곡 ID·검증용 메타데이터·시간이 있는 가사만 반환합니다. 내부 구조가 달라지거나 재생 정보를 확인할 수 없으면 다른 소스를 사용합니다.

디버깅 포트는 루프백에만 열려야 하며 외부 주소·다른 포트·다른 페이지·자격 증명이나 쿼리가 포함된 WebSocket은 거부합니다. 같은 PC의 다른 프로세스도 이 로컬 디버깅 연결에 접근할 수 있습니다. 자동 연결을 끄면 이후 자동 재시작을 중단하고 Spotify를 완전히 종료하면 연결도 닫힙니다.

## 빌드와 검증

Windows x64, .NET 10 SDK, Node.js가 필요합니다. Visual Studio는 필수가 아닙니다.

```powershell
pwsh -File scripts/test-windows.ps1
pwsh -File scripts/build-windows.ps1 -Run
```

SDK가 PATH에 없으면 `-Dotnet C:\path\to\dotnet.exe`를 전달하세요. 결과는 `build/windows/win-x64/`에 생성되며 `-OutputDirectory`로 변경할 수 있습니다. 가사 앱, WinUI 3 설정 앱과 런타임, 라이선스와 이 안내가 포함됩니다.

회귀 검사는 LRC 시간·간주·탐색, 후보 매칭, 응답·루프백 검증, 소스 우선순위·실패 대체·캐시·취소, 재생 시간 계산, 공유 Spotify 브리지와 Windows 곡 ID 추출을 확인합니다. 설정 앱의 WinUI 3 빌드도 검증합니다.

`SurfLyrics.exe --diagnostics C:\path\result.json`은 실제 UI·트레이·작업 표시줄·설정 앱과 Windows 미디어 API를 확인한 뒤 종료합니다. 곡명·가사·인증 정보는 진단 결과에 기록하지 않습니다.

### 2026-10-09 검증

Windows 11 x64 (빌드 26300), Microsoft Store Spotify 1.303.264.0에서 실제 동기화 가사 28줄을 Spotify 클라이언트 소스로 수신했습니다. 트레이 아이콘 우클릭에서 설정을 열고 WinUI 3 설정을 저장하는 동작을 확인했습니다. 가사 영역은 글자가 있는 위치에서도 클릭이 아래 창으로 통과하며 별도의 보조 가사 창은 포함하지 않습니다.

실제 WPF 창에서 왼쪽·오른쪽 이동과 일본어 가사를 포함한 4회 전환을 확인했습니다. Pretendard JP Light의 실제 glyph 굵기 300을 확인했고, 1,280.4 DIP 너비의 테스트 문장도 말줄임 없이 렌더링했습니다. 늘어나는 순간 알림 영역과의 겹침을 허용하고 이동 중 창 위치·크기는 고정됩니다. 기본 모니터 96 DPI/144Hz에서 이동 중간 프레임 104~116개, 중앙 렌더링 간격 약 6.93~6.95ms를 기록했습니다. 이는 렌더링 콜백 측정값이며 실제 표시된 프레임 수를 보장하지 않습니다.

120·250·400ms에 새 가사로 전환해 속도 연속성과 최종 정착을 확인했습니다. Windows 검사 113개, 공유 브리지 검사 18개, 현재 곡 추출 검사 11개가 통과했고 앱과 WinUI 설정창을 빌드했습니다. 모델의 60/120/144Hz 비교는 자동 검사이며 다른 모니터 DPI와 주사율을 실제로 변경해 검증하지는 않았습니다.

2026-10-10에는 실제 화면 전원 상태가 켜짐(1/1)인 환경에서 전체 프로브를 다시 통과했습니다. 4회 전환에서 이동 중간 프레임 102~114개, 중앙 간격 6.94~6.96ms를 기록했습니다. 같은 너비의 일본어 텍스트 교체, 중복 억제와 120/250/400ms 재타깃도 통과했습니다. 앞선 약 262ms 실패는 화면 전원이 꺼짐(0/0), WPF 일시중단 상태에서 나타난 기록으로 보존합니다. 생산 애니메이션 코드는 재검사 전후 같았습니다.

트레이 아이콘에는 macOS 앱의 컬러 파도·음표 디자인을 적용했고 16/20/24/32/40/48/64/128/256px 이미지를 포함했습니다. 원본 SVG로 다시 생성하려면 Windows에서 scripts/build-windows-icon.ps1을 실행하세요. --diagnostics 결과의 trayIconColored는 실제 NotifyIcon에 로드한 아이콘의 색상을 확인합니다.

「바래진 말들 — An da eun」은 Spotify 클라이언트 소스에서 동기화 가사 28줄을 수신했습니다. 일반 실행한 Spotify의 로컬 연결이 닫혀 있었으며 연결 준비 후 같은 제목·아티스트가 일치하고 LINE_SYNCED 응답이 반환됐습니다. Spotify를 일반 실행해도 자체 가사를 가져오려면 사용자가 허용한 Spotify 자동 연결 옵션을 켜두세요.

트레이 우클릭의 좌표 입력 재검사는 미검증 상태로 유지합니다. 설정창 로드와 클릭 통과는 실제 앱 진단에서 확인합니다.

Spotify의 비공개 클라이언트 구조는 업데이트로 바뀔 수 있습니다. 전체 음악 카탈로그와 이후 버전의 호환성은 검증 범위에 포함되지 않습니다.
