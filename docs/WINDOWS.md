# SurfLyrics for Windows

Windows 미디어 세션의 Spotify 또는 Apple Music 곡 정보와 재생 위치에 맞춰, 작업 표시줄 오른쪽 알림 아이콘 바로 왼쪽에 동기화 가사를 표시합니다. 가사 창은 WPF/.NET 10, 설정창은 **WinUI 3 네이티브**이며 macOS 소스와 별도로 `windows/`에 있습니다.

## 실행

Windows 11 x64 또는 .NET 10이 지원하는 Windows 10 LTSC/Enterprise x64 환경을 사용하세요. Windows API 대상은 Windows 10 2004 (19041) 이상입니다.

1. 배포 폴더 전체를 원하는 위치에 보관합니다. `SurfLyrics.exe`와 `Settings/` 폴더가 함께 있어야 합니다.
2. Spotify 또는 Apple Music 데스크톱 앱에서 음악을 재생합니다. Windows 미디어 컨트롤에 곡 정보를 제공하는 앱이어야 합니다.
3. `SurfLyrics.exe`를 실행합니다. 기본적으로 작업 표시줄에 가사를 표시하고 간주와 대기 상태에는 음표를 표시합니다.

.NET과 Windows App SDK 런타임은 배포 폴더에 포함되어 별도 설치가 필요하지 않습니다. 가사에는 **Pretendard JP 1.3.9**를 앱에 포함하여 사용합니다. 시스템 폰트 설치는 필요하지 않습니다.

가사를 클릭하거나 우클릭하면 가사 창·설정·재생/일시정지·가사 다시 불러오기·종료 메뉴가 열립니다. 메뉴의 배경과 글자색은 Windows 앱의 밝은/어두운 테마를 함께 따르고 고대비 모드에서는 시스템 색상을 사용합니다.

표시줄 배경이 보이는 투명 창을 알림 영역 옆에 배치합니다. 기본 모니터의 위쪽/아래쪽 가로 작업 표시줄에 맞춰 이동하고 자동 숨김 또는 전체 화면 앱에서는 숨깁니다. 긴 가사는 말줄임으로 표시하며 보조 모니터 작업 표시줄은 현재 지원하지 않습니다.

보조 가사 창은 트레이 아이콘 두 번 클릭 또는 가사 메뉴에서 표시합니다. 드래그 이동과 오른쪽 아래 크기 조정을 지원합니다. **고정**은 항상 위 옵션, **—** 또는 닫기는 트레이로 숨기기입니다. `--window`로 실행하면 보조 창도 표시합니다.

## 설정

WinUI 3의 네이티브 ToggleSwitch·Slider·Button·ContentDialog와 Mica 배경을 사용합니다. Windows 테마가 컨트롤의 색상을 결정합니다. 설정창은 별도 프로세스로 실행되며 현재 사용자만 접근 가능한 임시 이름의 named pipe로 가사 앱과 연결됩니다.

가사 소스, 자동 Spotify 연결, 작업 표시줄 표시·글자 크기, 보조 창 글자 크기, 항상 위 옵션, 시간 보정(-5~+5초), Windows 로그인 시 실행을 설정할 수 있습니다. 시간 보정이 양수이면 가사가 더 일찍 표시됩니다. 로그인 시 실행은 가사 앱 실행 파일의 경로를 저장하므로 폴더를 옮겼다면 다시 설정하세요.

**가사 전환 시 페이드**는 기본적으로 켜져 있습니다. 작업 표시줄과 보조 창의 가사가 바뀔 때 0.3초 동안 전환하며 끄면 즉시 바뀝니다. 빠른 탐색에서도 마지막 가사를 표시합니다.

설정은 `%LOCALAPPDATA%\SurfLyrics\settings.json`에 저장됩니다. 실제 가사, Spotify 쿠키와 접근 토큰은 파일에 저장하지 않습니다. Musixmatch 임시 토큰은 앱 메모리에만 보관합니다.

## 가사 소스와 Spotify 연결

켜진 소스를 **Spotify 클라이언트 → LRCLIB → Musixmatch** 순서로 확인합니다. 가사를 찾지 못하거나 요청이 실패하면 다음 소스로 넘어갑니다. 시간 정보가 없는 가사에는 시간을 만들지 않습니다. 곡 변경 시 이전 요청을 취소하고 이전 곡의 응답을 새 곡에 표시하지 않습니다.

LRCLIB와 Musixmatch는 Spotify 연결 준비 없이 사용할 수 있습니다. 제목·아티스트·길이·에디션을 확인하며 서로 다른 녹음이 모호하게 일치하면 선택하지 않습니다.

Spotify 자체 가사는 **설정 → Spotify 연결**로 준비합니다. 확인 후 현재 로그인된 Spotify를 `127.0.0.1:43827` 디버깅 연결로 실행합니다. Spotify가 다시 시작되면 음악이 멈출 수 있습니다. **Spotify 자동 연결**은 기본적으로 꺼져 있고 사용자가 허용하면 필요할 때 다시 시작합니다. 자동 재시도 간격은 최소 2분입니다.

일반 설치본과 **Microsoft Store 설치본**을 지원합니다. 일반 설치본은 실행 중인 앱 경로 또는 `%APPDATA%\Spotify\Spotify.exe`를 사용합니다. Store 설치본은 패키지를 찾고 Windows 앱 활성화 API의 기본 `Spotify` 진입점을 통해 실행합니다. 실행 파일 직접 호출이나 별도의 SpotifyLauncher 진입점은 사용하지 않습니다. 재시작 대상은 현재 세션에서 실행 경로가 확인된 Spotify 창입니다.

Windows 미디어 세션은 곡 ID를 제공하지 않습니다. Spotify의 현재 재생 링크가 곡을 가리키면 이를 사용하고, 앨범을 가리키면 현재 재생 컴포넌트의 제한된 상태에서 곡 ID를 확인합니다. 표시 제목·아티스트와 상태가 일치하고 곡 ID가 유일한 경우에만 가사를 요청합니다. React의 현재/대체 상태가 달라도 이전 곡을 선택하지 않도록 검증합니다.

가사 요청은 macOS와 같은 `SpotifyClientBridge.js`로 Spotify 내부의 인증된 클라이언트를 사용합니다. 인증은 Spotify 내부에 남고 곡 ID·검증용 메타데이터·시간이 있는 가사만 반환합니다. 내부 구조가 달라지거나 재생 정보를 확인할 수 없으면 다른 소스를 사용합니다.

디버깅 포트는 루프백에만 열려야 하며 외부 주소·다른 포트·다른 페이지·자격 증명이나 쿼리가 포함된 WebSocket은 거부합니다. 같은 PC의 다른 프로세스도 이 로컬 디버깅 연결에 접근할 수 있습니다. 자동 연결을 끄면 이후 자동 재시작을 중단하고 Spotify를 완전히 종료하면 연결도 닫힙니다.

## 빌드와 검증

Windows x64, .NET 10 SDK, Node.js가 필요합니다. Visual Studio는 필수가 아닙니다.

```powershell
pwsh -File scripts/test-windows.ps1
pwsh -File scripts/build-windows.ps1 -Run
```

SDK가 PATH에 없으면 `-Dotnet C:\path\to\dotnet.exe`를 전달하세요. 결과는 `build/windows/win-x64/`에 생성되며 `-OutputDirectory`로 변경할 수 있습니다. 가사 앱, WinUI 3 설정 앱과 런타임, 라이선스와 이 안내가 포함됩니다.

회귀 검사는 LRC 시간·간주·탐색, 후보 매칭, 응답·루프백 검증, 소스 우선순위·실패 대체·캐시·취소, 재생 시간 계산, 공유 Spotify 브리지와 Windows 곡 ID 추출을 확인합니다. 설정 앱의 WinUI 3 빌드도 검증합니다.

`SurfLyrics.exe --diagnostics C:\path\result.json`은 실제 UI·트레이·작업 표시줄·설정 앱과 Windows 미디어 API를 확인한 뒤 종료합니다. 곡명·가사·인증 정보는 진단 결과에 기록하지 않습니다.

### 2026-10-09 검증

Windows 11 x64 (빌드 26300), Microsoft Store Spotify 1.303.264.0에서 로컬 연결 실행과 실제 동기화 가사 수신을 확인했습니다. 곡이 바뀐 뒤에도 Spotify 클라이언트 소스로 43줄과 25줄의 가사를 각각 수신했습니다. 실제 작업 표시줄 표시와 WinUI 3 설정창의 앱 연결을 확인했습니다. Windows 검사 49개, 공유 브리지 검사 18개, 현재 곡 추출 검사 11개가 통과했습니다.

Spotify의 비공개 클라이언트 구조는 업데이트로 바뀔 수 있습니다. 전체 음악 카탈로그와 이후 버전의 호환성은 검증 범위에 포함되지 않습니다.
